# Quick Reference: Moving from Spreadsheets to CG Tennis OS Financial Tracking

Use this checklist when moving a player register, session log, money-received sheet, and renewal calendar into CG Tennis OS. The goal is to create one connected record per player while preserving coach judgement over make-up time, income entry, and renewal conversations.

> **Core rule:** Keep four truths separate. Participation answers whether a player took part. Session Credit records time owed. Manual Income records money already received. Packages and renewals record agreed coaching periods.

## 1. Prepare your spreadsheet data

| Check | Action | CG Tennis OS destination |
|---|---|---|
| ☐ | Remove duplicate player names and confirm the current guardian/contact details. | **Player Register** |
| ☐ | Identify active and inactive players. | Player status |
| ☐ | List recurring session offers with day, time, duration, format, location, and capacity. | **Programmes** |
| ☐ | Separate money already received from money still expected. | **Income** receives only confirmed money received. |
| ☐ | Identify any make-up time owed in minutes and the reason. | **Session Credit** |
| ☐ | Record current coaching period start/end dates and package terms. | **Packages & Renewals** |

## 2. Set up the operating structure

1. Create your **Programmes** first. Use Individual, Pair, or Group, then record schedule, duration, location, capacity, and notes.
2. Add each person to the **Player Register** once. Enter their enrolment date, current status, guardian/contact details, and Programme assignment.
3. Create a reusable **Package** for each agreed coaching offer. Link it to the matching Programme, then add duration and any private price reference.
4. Create or check each player’s current **Package Enrolment**. Confirm start date, renewal date, and notes before relying on the Renewal Tracker.

## 3. Replace the session attendance spreadsheet

| After each session | Record in CG Tennis OS | Do not use it for |
|---|---|---|
| Who took part | **Participation**: attended, absent, or excused. | Credit, payment, or renewal decisions. |
| Which session was delivered | A Programme-linked **Session** with all participants. | A substitute for Player Register details. |
| What happened in coaching | Session reflection and notes. | Proof of income received. |
| Time lost or owed | A separate **Session Credit** in minutes. | Changing attendance status. |

> A player may be marked **attended** and still be owed make-up time if a session is shortened. Record that time separately.

## 4. Replace the money-received spreadsheet

When money arrives, open **Income** and create a manual record. Enter the player, received amount, received date, method, and a concise note.

| Before saving manual Income | Confirm |
|---|---|
| ☐ | The money has actually been received. |
| ☐ | The correct Player Register entry is selected. |
| ☐ | Amount, date, and received method are correct. |
| ☐ | Any Session Credit shown is informational only; it does not change the amount. |

CG Tennis OS does not collect payment, apply a credit as a discount, create an invoice, or make a renewal decision automatically. Record only what the coach has confirmed.

## 5. Use Session Credit without mixing records

| If this happens | Coach action |
|---|---|
| Weather shortens a 60-minute session to 35 minutes. | Create a 25-minute Session Credit with the reason. |
| The player attends a make-up session. | Resolve the relevant credit manually after delivery. |
| A player misses a session. | Record the appropriate participation status; add credit only if the coach decides time is owed. |
| A player pays while time is still owed. | Record the income; leave the credit open until the make-up time is delivered or explicitly resolved. |

## 6. Run renewal conversations from the right context

Review **Renewals** 30 days before a coaching period ends. Open the player profile and check Programme, recent session history, open Session Credit, manual Income, and package history before the conversation.

| Renewal action | What the system does | What the coach still decides |
|---|---|---|
| Create a package renewal | Preserves the earlier period and creates a linked next period. | Whether to renew, the period terms, and when to record it. |
| Show Session Credit context | Displays open minutes. | How and when make-up time is delivered. |
| Show private package reference | Shows the stored coach reference. | Whether income has arrived; record it separately. |

## 7. Weekly five-minute review

- ☐ Complete reflections and participation for sessions delivered this week.
- ☐ Add or resolve only the Session Credit entries that reflect actual time owed or made up.
- ☐ Record confirmed money received in Income.
- ☐ Check the Renewal Tracker for upcoming and overdue coaching periods.
- ☐ Correct inactive player, Programme, or package status when a coaching arrangement changes.

## Before you stop using the old spreadsheet

| Final check | Complete when |
|---|---|
| ☐ Player Register | Every active player appears once with correct Programme and contact context. |
| ☐ Session history | Recent sessions include all participants and accurate attendance. |
| ☐ Credits | Open minutes are represented in Session Credit, not hidden in notes or attendance cells. |
| ☐ Income | Confirmed receipts are entered in the manual Income Ledger. |
| ☐ Renewals | Current package periods and renewal dates are recorded. |
| ☐ Spreadsheet archive | The old spreadsheet is retained as a read-only historical reference during the transition period. |

## Where to go next

| Coaching need | Open |
|---|---|
| Create or change a recurring offer | **Programmes** |
| Check one player’s full context | **Player Register** |
| Log delivery and participation | **Sessions** |
| Record time owed or made up | **Session Credit** from the player profile or session reflection |
| Record money received | **Income** |
| Plan the next coaching period | **Renewals** |
